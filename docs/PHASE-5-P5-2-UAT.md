## 0. 这一轮要证的是什么（**先读这一节，避免重复劳动**）

### 0.1 已由**机器**证明、本轮**不重验**的结论

> 来源：`docs/PHASE-5-P5-1-EVIDENCE.md`（P5-1 四组证据，基线 `297e728`）。

| 已证结论 | 来源 | 处置 |
|---|---|---|
| 短链 `/t/{token}` → **302** → `/h5/technician/visit/{token}`，且 `Location` 是**相对路径** | 证据 ④ ① ／ `verify-technician-routing` | ✅ 保留，**不重验**（除非手机端打不开，见 §6 阻断项） |
| 全部失效 Token 对外统一 **`401 TOKEN_INVALID`**，四种失效响应体**逐字节相同（68B）** | 证据 ① | ✅ 保留，不重验 |
| 照片 **magic bytes 判定** / EXIF+GPS 剥离 / 私有目录不可直读 / 属主绑定 | 证据 ② | ✅ 保留，不重验 |
| Submit **单事务原子性**（Visit→SUBMITTED / Ticket→WAIT_STORE_CONFIRM / Token 用后即焚 / 写事件） | 证据 ③ | ✅ 保留，不重验 |
| **0 张照片被服务端权威拒绝**（`422 PHOTO_REQUIRED`），"上传 1 张→失效到 0 张→仍拒" | 证据 ⑥b ／ submit 矩阵 P1~P4 | ✅ 保留，不重验 |
| 真实 Chromium 6 步闭环（含 DEV-80 收费分支）**全绿** | 证据 ④ | ✅ 保留，**但仍是"自动化视角"**，见 §0.3 |

### 0.2 本轮要证伪的命题

> **一个没参与开发、没看过页面的普通技师，拿着短信里那样一条链接，在真实手机上，**
> **能不能在不被告知"点哪里"的前提下，独立完成一次上门回执，**
> **并且看完结果后能用他自己的话分清：这是"已提交、等门店确认"，不是"工单已办结"。**

一句话：**机器已证明系统正确；P5-2 验的是"人能不能正确理解系统"。**

### 0.3 为什么这一轮**不能**由自动化替代

| 维度 | 自动化（CDP 真实浏览器）已经证明 | 自动化**证明不了** |
|---|---|---|
| 入口 | 探针能打开链接、step① 302 成功 | **真实手机**（微信内置浏览器 / 系统浏览器 / 不同分辨率）能否打开 |
| 操作 | 脚本能按选择器点中按钮、传文件 | 人**看不看得懂**要给哪张照片、按钮在不在拇指可及处 |
| 理解 | 断言页面**含**「已提交，等待门店确认」 | 人**读完之后是否真这么认为**——会不会理解成"已经结单了" |
| 语义 | 服务端回了 `WAIT_STORE_CONFIRM` | 人是否把"等门店确认"读成了"等我自己再处理" |

> ⚠️ **探针永远开全新 profile、永远拿最新产物、永远知道该点哪** ——
> 它测的不是真人的环境，也不是真人的心智。这正是 P5-1 期间 DEV-80 的教训：
> **API 层全绿 ≠ 页面走得通**；P5-2 再往前一步：**页面点得通 ≠ 人看得懂**。

### 手机可达性（**这是"手机端打不开"的前提，必须与产品缺陷区分开**）

本地 `PUBLIC_BASE_URL=http://localhost:8080` 里的 `localhost` **在手机上指向手机自己**，
因此**不能把 `node scripts/walkthrough-p5-1.mjs setup` 打印的原样短链拿去手机点**。
走查当天按下述步骤换成**手机可达的基址**（**只换 host:port，不动 token，也不改 `.env` 语义**）：

```bash
# ① 取主机 LAN IP（挑那个真实网卡地址，通常形如 192.168.x.x；
#    172.30.* / 192.168.190.* / 192.168.110.* 之类多为 Docker/WSL 虚拟网卡，勿用）
ipconfig            # 或 PowerShell: Get-NetIPAddress -AddressFamily IPv4

# ② 确认 8080 已发布到 0.0.0.0 且手机可打开
#    手机浏览器访问： http://<主机LAN IP>:8080/api/svc/health   → 期望 {"db":"ok","sms":"mock","tasks":"ok"}

# ③ 把 setup 打印的短链换成 LAN 基址（token 不变）：
#    http://localhost:8080/t/<token>   ⇒   http://<主机LAN IP>:8080/t/<token>
```

> ⚠️ **Windows 防火墙**：若手机打不开，先查是否为**入站规则拦了 8080**（属**环境问题，不是产品缺陷**）。
> ⚠️ **不要**为了方便把 `PUBLIC_BASE_URL` 永久改成 LAN IP —— 那是本机自测口径，
> 改动会污染 §9 闸门 3 的判据。走查用**临时替换链接**即可。

## 6. 阻断项 vs 非阻断项（**这一节决定 Phase 5 能不能关**）

### 6.1 阻断项（命中**任一** ⇒ **影响 Phase 5 最终关闭**，需另立 DEV 编号修复）

| # | 阻断项 | 说明 |
|---|---|---|
| B1 | **不会上传** | 在无提示下**找不到或完不成**照片上传 |
| B2 | **不会提交** | 填完回执后**无法完成提交**（按钮不可达 / 点了没反应 / 一直失败） |
| B3 | **误以为已经结单** | 把"已提交待门店确认"读成"工单已办结"（§5 问①命中） |
| B4 | **收费分支无法完成** | 本次收费场景下金额框不出现 / 填了提交失败（DEV-80 在真机回归） |
| B5 | **手机端实际打不开** | 手机从 `/t/{token}` 打不开页面（**须先排除环境不可达**，见 §1） |

> ⚠️ **B5 特别说明**：先按 §1「手机可达性」确认是**环境**还是**产品**。
> 若手机连 `http://<LAN IP>:8080/api/svc/health` 都打不开 ⇒ **环境问题**，不记 B5；
> 若健康检查能开、但 `/t/{token}` 打不开 ⇒ **B5 成立**（产品问题）。

### 6.2 非阻断项（只进 `docs/BACKLOG.md`）

- 间距 / 字体 / 字号 / 配色 / 图标视觉
- 文案不顺口、措辞可优化
- 字段名需要解释
- "能不能调起相机""能不能传更多张"等**超出本期口径**的诉求

> ⚠️ **两类问题必须分清**：
> **B3（误以为已结单）是语义问题，属阻断**；**"终态文案字体不好看"是视觉问题，属 backlog**。
> 把语义问题当视觉问题放过，正是 P5-2 存在的意义。

## 附 A：开场台词（**不许多说**）

> **"你手机上会收到（或我给你）一条链接，请打开它。**
> **就当这单今天你上门已经干完了 —— 该传的传上去，该填的填上，然后提交。**
> **弄完跟我说一声。"**

> ⚠️ **只说任务，不说操作方式**：不说"先传照片"、不说"选好处理结果"、不说"记得填金额"、
> 不说"按钮在右下角"、不说"至少传一张"。**"点哪里"不能说。**
>
> 说完 **闭嘴看着他操作**。他找不到按钮、点错地方、看不懂文案 —— 这些都是要走查的结果，
> 不是需要你立刻纠正的错误。开发人员站在旁边说"点这里、再点那里"，
> 只能证明功能存在，证明不了**师傅自己能用**。
