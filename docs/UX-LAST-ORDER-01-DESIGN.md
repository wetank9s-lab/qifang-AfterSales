## 一、现状事实（源码 + 接口实测）

### 1.1 客户侧

| 项 | 事实 |
|---|---|
| 提交成功后的凭证 | `POST /api/public/tickets` 响应一次性返回 `progress_token`（43 字符，库里只存 sha256）；成功页把它放在 URL `?pt=`，随后转成「查看处理进度」按钮 |
| 成功页 URL 参数 | `no`（单号）/ `pt`（进度 Token）/ `store`（门店名）/ `at`（时间）/ `type`（repair\|complaint）/ `k`（门店入口） |
| 进度链接 | 对外 `/p/<token>` → 302 → `/h5/customer/progress/<token>`；**进度页不再把 Token 放进任何请求参数以外的位置** |
| Token 有效期 | **未关闭 = 一直有效**；关闭后**保留 30 天**（`PROGRESS_TOKEN.RETAIN_DAYS_AFTER_CLOSE`）；可被显式**撤销**（`progress_token_revoked_at`） |
| Token 存在哪 | 数据库只存哈希；明文只出现在建单响应与客户手里的 URL |
| 浏览器本地存储 | **完全没有**最近工单：`localStorage` 零使用；`sessionStorage` 只有媒体授权标记（`svc-media-consent`） |
| 再次扫门店码 | 进入 `/report?k=<门店入口>`，页面只解析门店；**不会**读取任何"上一单" |
| 关闭浏览器后仍存在什么 | 只有浏览器历史/书签里的 URL（若用户保存）；**没有应用层持久化** |
| 能否按手机号/单号查 | **没有**这种匿名接口；进度查询只认 Token |

### 1.2 师傅侧

| 项 | 事实 |
|---|---|
| 链接形态 | `/t/<token>` → 302 → `/h5/technician/visit/<token>`（Token 43 字符，库里只存哈希） |
| 生命周期 | `technician.token_expire_hours` 默认 **72 小时**；提交后 `token_used_at` 写入 + Visit 状态离开 `ASSIGNED` ⇒ **原链接立即失效**（`ALREADY_USED` / `VISIT_NOT_ACTIVE`）；改派/取消会撤销旧链接 |
| 本地持久化 | 只有 `sessionStorage` 的「已提交」标记；**不保存 Token** |
| 提交后还能看到什么 | 页面显示"已提交"结果；**没有**"上一张服务工单"入口或接口 |
| 与客户进度页的关系 | **两个权限模型**：师傅 Token 可上传/提交；客户进度 Token 只读。**不得互换、不得复用** |

## 二、能否安全恢复？分三种需求看

| 需求 | 能否用现有凭证 | 结论 |
|---|---|---|
| 客户在同一设备、同一浏览器再看上一单进度 | **能**（进度 Token 在关闭前长期有效） | 可以，但必须**用户明确同意**才落盘，且要处理共享设备 |
| 客户换手机/换浏览器找回 | **不能**（Token 只在原设备；无身份体系） | 需另行设计（短信验证/单号+手机号验证），**不得假装本地存储能跨设备** |
| 师傅提交后回看"上一张工单" | **不能**（原 Token 提交即失效，这是安全设计） | **不得**本地保存旧 Token 绕过；需要新的只读凭据或登录体系 |

## 三、客户侧建议方案（推荐 A）

### 方案对比

| 方案 | 做法 | 风险/代价 |
|---|---|---|
| **A. 本机显式记住（推荐）** | 成功后用户勾选"在本设备记住这单"；仅存本机；再次进入**同一门店**时显示恢复卡片；可另选"自动进入" | 共享设备/公共手机会泄露；需清晰提示与一键清除 |
| B. 服务端匿名"最近一单" | 服务端按设备指纹/IP/手机号记忆 | 需要新的身份识别，**等于开一个"按手机号查单"的口子**；不做 |
| C. 短信找回 | 客户输入手机号，短信验证码后列出其工单 | 需要短信通道与验证码体系；**本期不做**，仅作为跨设备方向 |

### 推荐 A 的契约

**存储（仅前端）**

```
localStorage["svc.lastOrder.v1.<storeCode>"] = {
  ticketNo, progressToken, storeCode, ticketType, createdAt,
  savedAt, autoOpen: boolean, version: 1
}
```

- **按门店分区**：S01 的记录不可能在 S02 入口被读取（`storeCode` 来自服务端解析的入口，不取用户输入）；
- **默认不保存**：成功页提供勾选框（默认**不勾**），勾了才写；
- **自动进入**是**第二个**开关（默认关），只对"已选择自动恢复"的设备生效；
- **URL 优先**：地址栏里已有 `/customer/progress/<token>` 或成功页 `?pt=` 时，永远以 URL 为准，本地记录只作兜底；
- **展示前校验**：进入门店页时先用本地 Token 调 `GET /api/public/progress/<token>`：
  - 200 ⇒ 显示「上次提交 FW… · 查看进度」卡片（单号 + 时间，不显示客户姓名/手机号）；
  - 401/404/410 ⇒ **删除该条本地记录**并提示"上次记录已失效"；
- **清除**：卡片上有「不再记住」；设置/成功页也可清除；
- **过期自清**：`savedAt` 超过 30 天（或工单已关闭 + 30 天）自动删除；
- **不做**：不写 Cookie、不发第三方、不进日志/埋点、不把 Token 拼进任何外部请求；
- **共享设备提示**：勾选处明确写"公共手机请勿勾选；此记录只在本浏览器有效"。

**启动界面（报修页顶部）**

```
┌──────────────────────────────────────────┐
│ 四川七方连锁售后服务平台                  │
│ ┌ 上次提交 ────────────────────────────┐ │
│ │ FW20261017-0012 · 10-17 15:30        │ │
│ │ [ 查看进度 ]        [ 不再记住 ]      │ │
│ └──────────────────────────────────────┘ │
│ [ 我要报修 ] [ 我要投诉 ]                 │
└──────────────────────────────────────────┘
```

自动恢复条件（三者同时满足）：`autoOpen=true` + 校验 200 + 当前入口门店与记录门店一致。
否则只显示卡片、不跳转。

## 四、师傅侧建议方案（推荐 D）

| 方案 | 做法 | 结论 |
|---|---|---|
| D1 本地保存师傅 Token 复用 | 提交后仍存 Token 以便"回看" | ❌ **禁止**：Token 提交即失效是安全设计；本地保存等于绕过撤销/一次性语义 |
| D2 只存"完成摘要" | 提交成功后本地存 `{ticketNo, completedAt, summary}`，仅展示，不发请求 | ✅ 可作为"我刚做完的那单"提示；**不是**工单详情 |
| **D3 由门店重新签发只读回执链接（推荐后续）** | 门店在后台对某次服务生成"只读回执"短链（新 Token、只读、可撤销、短有效期） | 需要新接口/新 Token 类型；**本期只立契约，不实施** |
| D4 师傅登录体系 | 引入师傅账号 | 超出本期；与"匿名链接"定位冲突 |

**本期建议**：只做 D2（纯本地摘要，无 Token、无请求）；"继续查看上一张服务工单"入口**暂不做**，
等 D3 的只读回执契约评审通过。**明确不接受**任何"本地记住旧 Token 继续调接口"的做法。

## 六、真实验收场景（实施时按此验）

**客户**
1. 成功页不勾选 ⇒ localStorage **无**记录；
2. 勾选后 ⇒ 记录仅在当前门店 key 下，字段不含姓名/手机号；
3. 关闭浏览器重开同门店入口 ⇒ 卡片出现，点「查看进度」可打开；
4. 用 S02 入口打开 ⇒ **看不到** S01 的记录；
5. 工单被撤销/过期 ⇒ 卡片校验失败 ⇒ 记录被删除并提示；
6. 地址栏带合法 Token ⇒ 直接进进度页，不被本地记录覆盖；
7. 点「不再记住」⇒ 记录删除；刷新不再出现；
8. 共享设备：换一个浏览器（无痕）⇒ 无记录；
9. 网络/接口失败 ⇒ 不误删记录、不白屏（可提示稍后再试）。

**师傅**
1. 提交完成 ⇒ 原链接再打开 ⇒ 仍 401（安全设计不变）；
2. 本地只有摘要、无 Token（可在 DevTools 检查 storage）；
3. 新链接优先：门店重新派工的新 `/t/<newToken>` 永远覆盖旧摘要的展示。

## 七、明确不做 / 需要你确认

1. **不做**"按手机号或单号查任意工单"（会开遍历面）；
2. **不做**跨设备"自动同步"（本地存储做不到，不假装能做到）；
3. **不做**师傅旧 Token 复用；
4. 待确认：客户默认是否**永远不自动跳转**（推荐：是，必须用户点）；自动恢复开关是否按门店分别记忆（推荐：是）。
