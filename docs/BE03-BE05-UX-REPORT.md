## 2. 交互说明（页面级）

### BE-05 总部售后工作台
1. 顶部：统计日期 + 更新时间（北京时间）+ 刷新。
2. **今日发生量**（今日新增 / 今日完成）与**当前存量**（处理中 / 待门店确认 / 超过 24 小时未更新）
   分成两组，各自带一句"看什么"的说明，避免把两个口径混成一排数字。
3. 「展开指标说明」：5 条口径原文（来自 DTO 的 `definitions`，页面不自己编）。
4. **需要优先处理**：按"评价后继续处理 > 低分评价 > 超过 24 小时 > 待门店确认"排序，
   显示工单号/门店/状态/原因/最近更新；标题里写明"接口最多返回 50 条，不代表全部异常总量"。
   **没有放"查看工单"按钮** —— 现有 DTO 不提供可验证的跳转目标，按 §三.2 保留只读。
5. 门店对比：宽屏表格（最小列宽 640），窄屏卡片；10 家门店全列，0 也显示。
6. 近 30 天趋势：SVG 柱状（新增/完成双色），明细表收进「趋势明细」。

### BE-03 短信通知管理
1. **A 短信发送总状态**：总开关（已开启/已关闭/无法确认）+ 当前实际状态（允许发送/暂停发送/通道未就绪/无法确认）
   + 当前服务商，下面一条与结论一致的说明横幅。
2. **B 今日发送概况**：今日短信任务 / 因总开关暂停 / 其它原因未发送 / 服务商已受理，
   并明确写出"**送达情况暂无法自动确认**"（不把 `delivery_status=pending` 说成未送达）。
3. **C 通知场景设置**：七个中文场景 + 场景设置 + 当前实际状态 + 短原因 + 今日任务 + 被拦截 + 操作。
   总开关关闭时顶部固定提示「当前所有自动短信已暂停…」；关闭前必须确认（师傅任务/派工变更另有加重说明）。
4. **D 通道诊断及模板管理**：通道可用性（凭据已配/未配 + 人话原因）+ 模板标识受控编辑
   + 说明"短信宝按正文发送，模板标识对它不生效"。环境变量名与诊断原文收进「技术详情」。
5. **E 最近发送记录**：时间/场景/结果/说明/收件号码；错误码翻成人话；
   原始 `send_status` / `error_code` / `provider_request_id` / `provider_biz_id` 在「原始记录」里。

### 3.1 服务端那三处为什么必须改（都是"错但不报错"）
1. **`send_status='sent'/'failed'` 根本不存在**：`SMS_SEND_STATUS` 只有 `pending/accepted/rejected/error`。
   ⇒ 页面"服务商已受理"会**永远显示 0**（今天恰好也是 0，所以从截图上根本看不出来）。
2. **`alert_type` 判定顺序**：`overdue` 排在最前 ⇒ 一条"评价后被重开且超 24h"的工单被标成超时。
   实测 50/50 全是 `overdue`，"评价后继续处理 / 低分评价"两类**永远显示不出来**。
   ⇒ 只调整 CASE 顺序（评价后 > 低分 > 待确认 > 超时），阈值与统计口径未动。
   用 SQL 预演：`reopened=3 / low=3 / wait_confirm=0 / overdue=369`。
3. **场景中文名**：DTO 里仍是旧措辞（师傅任务取消/改派通知/进度链接通知/人工补发）。
   ⇒ DTO 已改；同时客户端对已知 7 场景**以本地表为准**，避免"服务端未部署时页面又显示旧词"。

> ⚠️ 以上服务端改动**尚未部署**，所以本轮截图里「需要优先处理」仍全部显示"超过 24 小时未更新"，
> 场景名靠客户端兜底才是新的。这属于**已知差异**，不是验证遗漏。

## 5. 响应式与中文化门禁

| 视口 | 整页横向溢出 | 中文逐字竖排 | 按钮被遮挡 |
|---|---|---|---|
| 1440×900 | 无（1440/1440） | 0 | 0 |
| 1024×768 | 无（1024/1024） | 0 | 0 |
| 800×600 | 无（800/800） | 0 | 0 |
| 390×844 | 无（390/390） | 0 | 0 |

判据实现（脚本 `ux-shot.mjs`）：
- 溢出：`documentElement.scrollWidth > innerWidth + 1`（表格内部滚动不算整页溢出）；
- 竖排：短文本元素 `width < 26 && height > 34` 计为逐字竖排；
- 遮挡：按钮中心 `elementFromPoint` 命中必须是自己或子孙。
  ⚠️ 第一版用"与 sticky/fixed 矩形相交"判，得出"5 个按钮被遮挡"的**假红**（按钮本来就在顶栏里）—— 已改。

中文化：场景名、状态、错误原因、诊断原因全部中文；`SMS_*` 错误码与 `ALIYUN_SMS_*` 环境变量名**只出现在「技术详情」**。
