## 二、为什么不从旧分支直接覆盖

旧分支（`r2.1-ui-fix` / 含口令历史）与 R2.1.2 的差异包含：
- `docs/` 大量、`scripts/` 大量、以及**含明文口令的历史提交**
- 桌面端 client 代码（R2.1.2 已在此之上做了按钮统一 + 菜单 4+10）

若整体 checkout，会把桌面端回退到 R2.1.1 之前的状态。
本轮只取「生产缺失且已验收」的 `src-mobile/**` 与 `scripts/deploy-mobile-remote.py`，
其余一律沿用 R2.1.2。

## 三、部署方式（可 dry-run / 可回滚）

工具：`scripts/deploy-mobile-remote.py`

```
S6_SSH_PASS=… python scripts/deploy-mobile-remote.py --dry-run
S6_SSH_PASS=… python scripts/deploy-mobile-remote.py --apply
S6_SSH_PASS=… python scripts/deploy-mobile-remote.py --rollback <stamp>
```

1. **备份**：`/opt/scqf-aftersales/backups/mobile-<stamp>/`（原 `/m` 目录 + `nginx.conf`）
2. **上传到 staging → 原子切换**：先传 `.m-staging-<stamp>`，回读哈希逐一比对，再 `mv` 成 `/m`
3. **nginx 只做锚点插入**：插在 `location ^~ /h5/` 闭合之后；插入前静态自检「原有每个 `location` 行都必须仍存在」，
   已实测原有 20 个 location 全部保留、新增 3 个
4. **`nginx -t` 失败立即恢复**：从备份目录回拷配置，不 reload
5. **HTTP 自测**：`/m/`、`/m/search`、`/m/favicon.svg` 逐一取状态码与字节数

### 受保护路由（计数在插入前后必须逐一相等）

`/p/t/`、`location /p/`、`location /t/`、`location /f/`、`location /h5/`、`/api/public/`（含 media upload/session/files、progress、banner、reviews、store-entry、tickets）、
`/files/`、`/api/publicArchive:queryByMobile`、`^~ /api/publicArchive:` → 403、`/api/technician/*` 全部 rewrite。
实测插入前后计数全部一致（`/h5/` 多 1 处仅因 `/m/` 段注释里引用了它）。

## 五、收敛决定

`PoC.tsx` 与 `ComponentGallery.tsx` 是开发期的组件/接口验收页，**不是业务流程**。

本轮处置：**随产物上线但不接入导航**（`/m/poc`、`/m/components` 仅开发知情可达），
并在 `router.ts` 保留其路由。原因：移除会增加构建改动面与回归风险，且它们不触碰任何写接口。

> 若后续要求彻底移除，单独立项做（只需删两页 + 两条路由，不涉及后端）。
