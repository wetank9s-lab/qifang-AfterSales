## 零、走查前 30 秒（**组织者做，真人到场前完成**）

1. 跑标准入口，确认前哨全绿：

   ```bash
   node scripts/uat-reset-baseline.mjs
   ```

2. 造走查夹具，记下打印出来的**短链 / 工单号 / Visit id**：

   ```bash
   node scripts/walkthrough-p5-1.mjs setup
   ```

3. **换成手机可达的基址**（只换 `host:port`，token 不变，**不改 `.env`**）：

   ```
   http://localhost:8080/t/<token>   ⇒   http://<主机LAN IP>:8080/t/<token>
   ```

4. **手机先自测一次网络**：手机浏览器打开 `http://<主机LAN IP>:8080/api/svc/health`
   → 期望 `{"db":"ok","sms":"mock","tasks":"ok"}`。
   **打不开就先修环境（防火墙 / 端口发布），别把环境问题记成产品缺陷（B5 的判据见 §四）。**

5. 记下前哨 **§3.8** 打印的「客户端产物构建标记」，填到本页顶部。

> ⚠️ 为什么要换基址：`PUBLIC_BASE_URL=http://localhost:8080` 里的 `localhost`
> **在手机上指向手机自己**，原样短链在手机必然打不开 —— 那是**环境**，不是产品坏。

## 六、操作后服务端复核（不依赖界面）

```bash
docker exec svc-postgres psql -U svc_app -d service_ticket -c \
  "select visit_no, visit_status, service_result, is_charged, reported_charge_amount, \
          (token_used_at is not null) as token_used, submitted_at \
     from service_visits where ticket_id=<ticket_id> order by visit_no;"
docker exec svc-postgres psql -U svc_app -d service_ticket -c \
  "select status, completed_at, reviewed_at from service_tickets where id=<ticket_id>;"
docker exec svc-postgres psql -U svc_app -d service_ticket -c \
  "select photo_type, mime, size, sort_order from service_visit_photos where visit_id=<visit_id> order by sort_order;"
docker exec svc-postgres psql -U svc_app -d service_ticket -c \
  "select event_type, from_status, to_status, summary, metadata from ticket_events where ticket_id=<ticket_id> order by id;"
```
