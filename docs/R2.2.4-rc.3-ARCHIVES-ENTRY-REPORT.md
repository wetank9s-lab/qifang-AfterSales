# R2.2.4-rc.3 · 后台「上门服务档案」入口缺失 — 根因与修复

> 指令日期：2026-11-25
> 状态：**代码与迁移完成，隔离预演通过，未部署生产**
> 保留 tag：`r2.2.3-rc.2` / `r2.2.4-rc.1` / `r2.2.4-rc.2`（均未改动）

## 一、根因（8 项逐条核实）

**结论：属「页面和路由在库里根本不存在」，不是角色授权、不是缓存、不是菜单分组。**

| # | 核查项 | 实测结果 |
|---|---|---|
| ① | 桌面后台是否已建档案页面 | `desktopRoutes` 36 行 / `flowPage` 15 个，**逐个点名无**「上门服务档案」 |
| ② | `desktopRoutes` 是否有真实页面节点 | 无 |
| ③ | `rolesDesktopRoutes` 角色关联 | 八角色全部不含该页 |
| ④ | `listAccessible` 是否返回入口 | 平台超管返回 **14 个叶子页**，逐条核对**无** |
| ⑤ | `menu-groups.ts` 虚拟分组是否遗漏 | GROUP_DAILY 本就 4 项；它是**纯前端 DOM 重组**，不产页、不产生权限节点 |
| ⑥ | `ROLE_MENU_MATRIX` 是否包含档案 | **已包含**（不是矩阵漏了） |
| ⑦ | `ROLE` / `ROLE_ROLE_NAME_MAP` / 服务端权限是否一致 | **一致**，`ARCHIVE_ADMIN_LIST_ROLES` 含 4 个业务角色 + root/admin |
| ⑧ | 管理员为何看不到 | `listAccessible` 只返回库里真实存在的路由 |

**决定性证据（把"缺代码"与"缺配置"分开）**：

```
生产 dist/server/index.js   : archiveAdminList 出现 3 次
生产 dist/                  : ServiceArchivesAdminModel 出现 13 次
生产 dist/                  : archiveProductList 出现 0 次
```

⇒ 后台页面的**模型代码早已上线**，只是**数据库里从未注册页面节点**。

**为什么会这样**：页面历来靠 `scripts/seed-admin-pages.mjs` **手工播种**，而生产 42 条迁移里**没有任何一条**负责建后台页面。代码写了、本地跑过，但从没在生产执行过 —— 而它不会报错，只是菜单里少一项。

## 二、最小修复

### 2.1 新增幂等迁移（唯一的结构变更）

`nocobase/plugins/service-ticket/src/server/migrations/202611251-archives-admin-page.ts`

- `on = 'afterLoad'`（`flowModels` / `desktopRoutes` 由插件建表）
- **不猜 UID**：父分组按 `title='售后工单'` 现查，查不到即 throw；生产与本地不同构
  （实测：总部售后工作台 生产 `qke3hyq3v92`、本地 `zku15hcn09u`）
- **只 INSERT，不 UPDATE / 不 DELETE** 任何既有行
- `desktopRoutes.id` 走 `repo.create()`（由 `SnowflakeIdField` 生成，**不自己拼**）
- `rolesDesktopRoutes` 走原始 SQL + 显式 `now()` + `ON CONFLICT DO NOTHING`

**授权覆盖三样（这是修复过程中发现的关键缺陷）**：

| 目标 | 为什么必须 |
|---|---|
| **分组节点** `type='group'` | `listAccessible` 按树裁剪：根分组没授权 ⇒ 整棵树返回 `[]` |
| **页面** `type='flowPage'` | 菜单项本身 |
| **页面的 Tab** `type='tabs'` | 只授页面不授 Tab，菜单能出但点进去 Tab 缺 |

⇒ **4 角色 × 3 节点 = 12 条授权**，回查**逐角色 × 逐节点**核对。

### 2.2 权限范围（按用户裁决收窄）

`PAGE_ROLES = ['store_sales', 'store_manager', 'hq_admin', 'hq_after_sales']`

- **`store_after_sales` 移除**：它不在 `ARCHIVE_READ_ROLES` / `ARCHIVE_ADMIN_LIST_ROLES` 里，
  给了菜单也只会点开 403
- 同步从 `scripts/expected-sensitive-columns.mjs` 的 `ROLE_MENU_MATRIX`
  删除 `store_after_sales` 的「上门服务档案」项
- `viewer` 始终不给（用户 2026-11-09 定）

### 2.3 后台管理页（复用既有 action，不新增数据源）

`service-archives-admin-model.tsx` 从"纯只读八列表格"扩为管理页：

- 分类（全部 / 上门服务 / 暖通工程）+ 四条件查询（编号 / 姓名 / 手机号 / 门店）
- 9 列列表（档案编号 / 客户 / 业务类型 / 所属门店 / 服务进展 / 计划·实际 / 操作）
- 详情：客户与地址 / 业务信息 / 产品清单 / 暖通六阶段 / 照片分类计数 / 内部备注
- 普通服务可改：`planned_date` / `service_date` / `notes` / `assigned_worker`（带乐观锁）
- **全部走 `svc:*` 受控 action**，不直连 `serviceArchives` 原生 CRUD

### 2.4 门禁修正

`verify-config.mjs` 与 `.env.example`：8 个测试凭据按两条不同门禁路径处理
（`_PASSWORD` 进白名单必须是注释形态；`ARC_TEST_PW` 不匹配 `_PASSWORD`，必须在模板里
以赋值形态出现）；3 个真实运行配置补模板。**未扩大白名单覆盖真实账号口令。**

## 三、隔离预演（生产三表 dump → 独立 PG 容器）

环境：`svc-page-rehear`（`postgres:16`），导入 `desktopRoutes` / `flowModels` /
`rolesDesktopRoutes` 的结构与数据，行数 **36 / 2171 / 166**（与生产一致）。

| 检查项 | 结果 |
|---|---|
| 首次执行 | 页面 1 / Tab 1 / 区块 1 / 授权 **12** ✔ |
| 连跑第 2 遍 | **新增全 0**（幂等）✔ |
| 连跑第 3 遍 | 新增全 0 ✔ |
| 区块挂载 `options.parentId` == Tab `schemaUid` | `t` ✔ |
| 回滚：DELETE 12+1+1+1 | 行数精确回到 **36 / 2171 / 166** ✔ |
| 回滚后重跑迁移 | 再次成功（可反复上下线）✔ |
| **既有行指纹**（迁移前后同口径） | 三表 md5 **逐字节相同** ✔ |
| 分组可达性 | 迁移前 **f** → 迁移后 **t** ✔ |
| `store_sales` 可见页面 | 迁移前只有孤儿 → 迁移后 **上门服务档案** ✔ |

**「不覆盖旧迁移、不删已有节点」的判据**是通过比对既有行指纹，而非肉眼：

```
             迁移前                                              迁移后
desktopRoutes |36|25fe9e72a81acde2d0511ebddcbcc900  →  同值
flowModels    |2171|a8c4b859ee377aadc292f14bfbb52f2f →  同值
rolesDesktop  |166|5f925f309dbafe68f4fb4c52c8c68ded  →  同值
```

**孤儿授权 8 条**：生产 `rolesDesktopRoutes` 里本来就有 8 条指向已删除路由，
隔离库基线同为 8，迁移前后不变 ⇒ **与本迁移无关**，迁移不碰它们。

**回滚方案**：`scripts/rehear-rollback.sql`（按 `title` 与 `parentId` 定位，
不按 id 猜；先删授权 → 再删区块 → 再删 Tab → 最后删页面）。

### 4.2 §四 问题 B —— 定位到两处，均与"表未建"无关

| 账号 | 角色 | `svc:archiveAdminList` | `serviceArchives:list`（原生） |

⇒ 两处都是**正确的权限行为**，**与"是否建产品清单表"无因果**。
