## 2. 404 来自哪一层？—— **服务端路由缺失（应用级 404），根因在 Nginx 缺少 rewrite**

未认证探针对比（同一个应用进程）：

| 请求 | 状态 | Content-Type | 响应体 |
|---|---|---|---|
| `GET /api/svc/visits/2638` | **404** | `text/plain` | `Not Found` |
| `GET /api/svc:visits/2638` | **401** | `application/json` | `{"code":"EMPTY_TOKEN"}` |
| `GET /api/svc/ticket/6915` | **404** | `text/plain` | `Not Found` |

判读：**action 路由是存在的**（`/api/svc:visits/...` 能进到鉴权），
而 REST 形态 `/api/svc/visits/:id` **在应用里根本没有注册** ⇒ 404 是 NocoBase/Koa 的默认 404，
不是权限拒绝、也不是业务 `VISIT_NOT_FOUND`（那会返回 JSON 错误码）。

有效配置证据（`nginx -T` 与站点文件双向核对）：

```
站点文件：/www/server/panel/vhost/nginx/sh.scqfls.cn.conf   （mtime: 10-23 11:01）
  含 rewrite 的只有：/api/public/*、/api/technician/visits/*
  grep "svc/visits" → 0 命中
  （文件里出现的 "svc" 只是变量名 svc_progress_token / svc_visit_token）
```

而客户端产物里写得很清楚（`dist/client/index.js:1026-1031`）：

> 对外路径 `/api/svc/visits/:id`，**由 nginx 重写成 `/api/svc:visitDetail?filterByTk=<visitId>`**

⇒ **契约要求的重写规则在现行配置里不存在**。

**附带发现（时间线）**：该 conf 的 mtime 是 **10-23 11:01**，而 P6-0/P6-2 曾验证过 I11 200。
高度怀疑那次配置被**重新生成/覆盖**时丢了 `svc` 段（不是本次媒体改造直接改坏的）。

### 建议的最小配置差异（**待授权，未执行**）

在 `sh.scqfls.cn.conf` 的 `location / {`（或既有 `/api/` 反代块）内、**`proxy_pass` 之前**插入：

```nginx
# I12/I13 必须排在 I11 之前（否则两段式被单段式先吃掉）
rewrite "^/api/svc/visits/([0-9]+)/confirm$" /api/svc:visitConfirm?filterByTk=$1 break;
rewrite "^/api/svc/visits/([0-9]+)/reject$"  /api/svc:visitReject?filterByTk=$1  break;
```
