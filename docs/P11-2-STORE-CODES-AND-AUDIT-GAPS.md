### 🔴 为什么"地名唯一"不足以绑定（本项的核心判断）

直觉是"地名在 15 家里唯一 ⇒ 可以对应"，但**现有数据本身就否掉了这条规则**：

```
S03  圣大家电金堂店   region=成都市金堂县
S04  金堂华林电器     region=成都市金堂县      ← 同一个县里有**两家**
```

⇒ 一个地名可以对应多家门店。"新津只有 S05 一家"这句话**从未被证伪过**——
它只说明占位清单是"一县一家"造的，推不出"真实门店也一县一家"。
按用户"匹配无歧义"的标准，地名命中而品牌完全不同就是**有歧义** ⇒ **不更新**。

### ⚠️ 关于"签名不变 ⇒ 改名不影响旧二维码归属"——**不能这样默认**（用户点名）

事实分两半，必须分开说：

| 维度 | 会不会变 | 说明 |
|---|---|---|
| 入口签名 / URL / 二维码图像 | **不会变** | 签名材料只有 `store-entry:${code}`（源码断言 + 重复重算一致）；改 `name`/`address` 在密码学上不可能改变它 |
| **人看到的门店归属** | **会变** | 已印出的二维码进入页面后，门店卡显示的是**数据库里的名称**。原来印着"圣大家电新都店"的码，现在显示"新都圣大家电" |

⇒ 所以"签名没变"**只证明链接没失效**，**不证明归属于谁没变**。
若某家门店的占位码当初是按**另一个片区**发出去的，改名就把"那个码现在指向哪家店"改掉了。
**本实例的实测结论**：只有 S01/S04 被改，而这两家的工单几乎全是验收数据（S01 155 张里 3 张非夹具、S04 为 0），
**因此本轮改名对真实业务归属的实际影响≈0** —— 但这是**实测结论**，不是"签名不变所以没事"的推论。

### 结论（可信的风险判断，不含推测）

1. **修复确实生效且可量化**：`store` 类事件 **修复前 0/251**、**修复后 3/3（100%）**。
   这条已做成**回归判据** —— DEV-137 若复发（例如哪天又有人把键名写回 `operatorUserId`）会立刻变红。
2. **"全库 100% NULL"这个说法只在"修复前"成立**：`operator_kind` 三类事件
   （`customer` / `system` / `sms_*` / `reviewed`）**在设计上就没有操作人**，不属于缺口；
   把它算进"缺口"会让风险看起来比实际大。
3. **真实缺口 = `store 251` + `technician 8` = 259 条**（修复前的部分）。
   其中：
   - `technician 8` 条：操作者靠师傅 Token 认定，`visit_id` 可定位 Visit，但**不是 `users.id`** ⇒ 无法回填成某个员工；
   - `store 251` 条：`metadata_json.request_id` **非空 0 条** ⇒ 与"编码了 userId 的幂等键"**没有任何可证明的连接**。
4. **唯一可证明的窄路**：`remote_completed` 事件中 **52 条**可由幂等键
   `${ticketId}:${userId}:${requestId}` 的**基数唯一性**（该工单 1 条记录 + 1 条事件）证明操作人。
   **本轮未执行任何回填** —— 是否执行属发布决策，且执行时必须留下推断依据。
5. **不可证明的部分一律标为历史数据缺口**，进发布前风险清单（R3）。

### 测试窗口与限流桶约定（用户要求"明确记录"）

- **受影响的桶**：`publicStore:entry` / `publicTicket:create` 共用 **IP 分钟桶**（`security.ip_minute_limit`）；
  另有一条 **手机号日桶**。
- **实测现象**：`verify-store-entry.mjs`（大量匿名请求）紧接 `smoke-test.mjs` 跑 ⇒
  smoke 的 Phase3 出现 6~9 条 **429 假红**（115/124）；**等 70 秒**让分钟窗口过期后单独跑 = **124/124**。
- **约定**：
  1. **同一 IP 的匿名门禁串行跑，且相邻两支之间等待 ≥ 70s**（或先跑不含匿名请求的门禁）；
  2. **不改限流阈值**（用户明令"不放宽既有安全限流"）；
  3. **判据上区分**："429 出现在本该成功的第一发"视为**测试窗口冲突**；"正常用户路径出现 429"仍按**产品缺陷**处理 ——
     这条区分由 smoke 自己那支"阈值=2 时序列必须是 200,200,429"的断言把守（它证明限流生效且可解释）。
