## 二、经典 iOS 设计 Token 跨前端统一

### 结论：H5 主色/背景/表面原本已对齐，真实差距在**字号**

| 项 | 改动前 | 改动后 |
|---|---|---|
| `h5/src/styles/base.css` | 14/16/18/21/24/34px + 12.5/13.5/14.5 半像素，共 39 处硬编码 | 全部走 `var(--svc-fs-*)`，残留 **0** |
| `h5/public/archive.html`（客户查进度正文页） | 12.5/18/16/15.5/11.5px | 六档变量，残留 **0** |
| `src-mobile/src/styles/app.css` | `body` **从未设字号**，16px 是浏览器默认 | 显式钉 17px |

**为什么 `body` 那条是真缺陷而不是吹毛求疵**：
16 不在六档里 ⇒ 任何**漏写 `.qf-*` 类**的元素都静默落在 16px 上，层级断一档，
而这种样式漏写**不会报错**；另外 iOS 在 `<input>` 字号 <16px 时聚焦会自动放大页面。

### 门禁 `verify-h5-design-parity.mjs`（10/10）

| 判据 | 内容 |
|---|---|
| T1–T3 | 背景 `#F2F2F7` / 表面 `#FFFFFF` / 主色 `#007AFF` 与移动端逐键同值 |
| T4 | 六档 `TYPE_SCALE` 与 `--svc-fs-*` 逐键同值（**解析失败必须表现为红**） |
| T5 | base.css + archive.html **都不得**残留硬编码字号 |
| **T5b（本轮新增）** | archive.html 的六档**值**必须与 base.css 逐键相同 |
| T6–T9 | 触控 44/52、禁毛玻璃/深色/999px、圆角 9–16、品牌常量 |

**T5b 是这轮补的洞**：原先只扫 `base.css`，而客户「查进度」的正文页是
**静态 HTML**，不经过 React 构建 ⇒ 它有 5 种非档位字号，门禁却一直绿。
只验"有没有用变量"不够，必须逐键比**值**。
变异自证：把 archive.html 的 body 改成 16px ⇒ T5b 立刻红，还原即绿。

## 三、测试数据清理边界

事故根因（写进 `scripts/lib/test-data-scope.mjs` 文件头）：
**清理的触发点依赖"已经取到 id"这一前提，而 id=370 那次异常恰好发生在这个前提之前。**

| 用户要求 | 实现 |
|---|---|
| 唯一运行标记 | `newRunTag('FIN')` → `R221FIN<6位hex>` |
| 创建前建立保护范围 | `openScope({ run })`，**标记不足 8 位直接抛**（空标记 = 全表） |
| 记录真正创建的 id | `scope.track(id, note)`，只收正整数 |
| 只用精确 id 或唯一标记 | `resolve()` 先按 id，再按 `LIKE '%RUN%'` 兜底找回 |
| **不得凭普通手机号删** | 源码**没有任何**按手机号删除的分支（Q1 静态断言） |
| 清理后核对 | `verify()` 逐表残留计数 |
| 异常显式报告 | 残留非 0 / 行数不符 → 抛错，错误信息带运行标记 |

`verify-test-data-scope.mjs`（8/8，内存桩 psql，**不连真库**）：
Q5 专门证明「一次 `track` 都没调用时，靠运行标记仍能找回 `[370,371]`」——那就是事故的正解。

**本轮实测**：每次验收跑完 `service_archives WHERE customer_name LIKE 'R221%'` = **0 条残留**，
四张子表全部归零。
