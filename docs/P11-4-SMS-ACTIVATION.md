# 短信开通清单（运营 / 上线准备）

> 面向**运营与上线**，不是技术报告。目标：把"客户提交后收到一条含进度链接的短信"这件事开通。
> ⚠️ 本文件**不得**写入任何 AccessKey、明文查询 Token 或客户数据。

---

## 一、要准备的四件事

| # | 事项 | 说明 | 配到哪个变量 |
|---|---|---|---|
| 1 | **正式 HTTPS 公网域名** | 已备案、解析到本服务、证书受信、走 443 | `PUBLIC_H5_BASE_URL=https://<域名>` |
| 2 | **短信签名** | 建议 **【七方售后】**（**以审核结果为准**） | `ALIYUN_SMS_SIGN_NAME=<审核通过的签名>` |
| 3 | **短信模板（首条）** | 见下方第二节 | `ALIYUN_SMS_TPL_PROGRESS_LINK=<TemplateCode>` |
| 4 | **通道与凭据** | 通道切 aliyun；AccessKey **已在服务器上配置**（不在本文件） | `SMS_PROVIDER=aliyun` |

> 第 1 项的域名**必须是公网可解析的 HTTPS**：本项目在 **production 档会拒绝启动**，
> 若写成 `localhost` / `192.168.x.x` / 内部端口，服务**起不来**（这是有意的护栏 ——
> 门店二维码是印出去贴在墙上的，错了无法召回）。

---

## 二、首条模板（拟申请）

**模板名称**：售后申请提交通知

**模板正文（拟）**

```
您的售后申请已提交，工单号${ticket_no}。查看处理进度：${link}
```

**签名**：`【七方售后】`（以审核为准）

### ⚠️ 变量名必须与"审核通过的模板"对齐

| 供应商模板里的变量 | 本系统实际传的参数名 | 何时对得上 |
|---|---|---|
| `${ticket_no}` | `ticket_no` | 一致 ✓ |
| `${link}` | `link` | 一致 ✓ |

- 若审核回来的模板把变量改成了别的名字（例如 `${orderNo}`、`${url}`），
  **必须以审核通过的为准，由开发改代码里的参数名** —— **不能在业务代码里猜参数名**。
- 阿里云的链接类变量可能有**单独的审核要求**（例如需要备案域名、不允许短链等）。
  若 `link` 被要求改成完整长链，同样以审核结论为准，开发侧改传参。

## 三、其余短信场景（按需申请，不擅自启用）

现有 6 个场景都需要各自的 TemplateCode；**本轮只要求第 3 项（进度链接）**，
其余按业务需要再申请，**不擅自增加自动发送场景**：

| 场景 | 变量名 | 环境变量（补齐后应为非空） |
|---|---|---|
| 客户受理通知 | `label` / `ticket_no` / `store` / `technician` / `expected` | `ALIYUN_SMS_TPL_DISPATCH_CUSTOMER` |
| 师傅任务 | 见模板系统 | `ALIYUN_SMS_TPL_TECHNICIAN_TASK` |
| 师傅作业取消 | 见模板系统 | `ALIYUN_SMS_TPL_TECHNICIAN_ASSIGNMENT_CANCELLED` |
| 进度变更通知 | 见模板系统 | `ALIYUN_SMS_TPL_DISPATCH_UPDATE` |
| 评价邀请 | 见模板系统 | `ALIYUN_SMS_TPL_REVIEW_INVITE` |
| **进度查询链接（本轮）** | `ticket_no` / `link` | **`ALIYUN_SMS_TPL_PROGRESS_LINK`** |

> 👆 这 6 行**已在 `.env.example` 与 `.env` 中就位（值为空）** —— 运维只需填值，
> 不需要记"要加哪个键"。（本轮补了此前**两边都缺**的两行。）

## 四、开通前的验证步骤（按顺序做）

1. **域名可达**
   ```bash
   curl -I https://<域名>/api/svc:health      # 期望 200
   ```
2. **基址合规**：把 `PUBLIC_H5_BASE_URL` 设为 `https://<域名>`（不要带端口）后重启；
   服务能起来 = 基址通过了生产校验。
3. **签名与模板就位**：6 个模板变量与签名**都不为空**。
4. **通道就绪但先别开发送开关**：
   - 用**运营自己的手机号**提交一张测试单；
   - 查 `sms_logs`：该单应出现 `scene=progress_link`，且 `send_status` 不是
     `pending`（`SMS_TEMPLATE_NOT_CONFIGURED` 说明模板 CODE 还没填对）；
   - 手机上应收到短信，**点链接能打开那一张工单**。
5. 确认第 4 步无误后，再打开总开关：`SMS_ENABLED=true`。
6. ⛔ **不得为了"让它发出去"而修改生产校验、硬编码内网 IP、或把域名写成本机地址。**

## 六、两条**不要动**的既有契约

1. **进度 Token 可重复使用**：客户在有效期内可**反复查询**（刷新进度页、多次打开链接都行）。
   已用"连续查询 3 次都成功"的门禁钉住 —— **不要**把它改成"看过一次就失效"。
2. **无法安全恢复凭证的历史短信不自动补发**：库里的 `progress_link` 正文含一次性 Token
   且**正文不落库**，所以系统在异常恢复时会把它标为
   `SMS_PENDING_ORPHAN_UNREBUILDABLE`（**保守不补发**）。这是刻意设计，**不要改成抢发**。
