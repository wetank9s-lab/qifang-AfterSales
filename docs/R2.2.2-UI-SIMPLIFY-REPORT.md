## 二、六阶段逐项检查结果（用户第五节第 1 条：不能只查一个）

对象：`DEMO-R2221-B`（id=395，六阶段全完成，隔离演示数据）。逐一点「修改」→ 抓面板 → 抓图 → 取消。

| 阶段 | 照片要求 | 整改前字数 | 整改后字数 | 整改前面板高 | 整改后面板高 |
|---|---|---|---|---|---|
| 现场勘察 survey | 必需 | 104 | **78** | 568 | **526** |
| 方案确认 plan | 非必需 | 87 | **74** | 542 | **526** |
| 管路施工 pipe | 必需 | 104 | **78** | 568 | **526** |
| 设备安装 device | 必需 | 104 | **78** | 568 | **526** |
| 调试运行 test | 非必需 | 87 | **74** | 542 | **526** |
| 客户验收 accept | 必需 | 104 | **78** | 568 | **526** |

**删掉的具体是这两句**（整改前原文）：

1. `"直接改这里的日期、备注和照片，保存后阶段状态不变，后面已完成的阶段也不会退回去。"`
   —— 用户明令：「这是系统内部逻辑，不需要向销售人员解释。」
2. `"这个阶段至少要有 1 张现场照片才能完成。"` / `"…要换照片，请先点「添加照片」传新的，再移除旧的。"`
   —— 与照片区已有的 `0 / 6` 计数和「添加照片」按钮重复。

**整改后面板只剩**（六阶段完全一致的结构）：

```
修改「现场勘察」          ← 当前阶段名称
现场照片  0 / 6  [添加照片]
上传本阶段现场照片，最多 6 张（至少 1 张）    ← 提示收敛为一句
阶段日期  [2026/09/30]                      ← 与时间线一致（缺陷 #7 已修）
填写本阶段处理情况（选填）                    ← 备注标签简化
客户看不到，只有门店和总部能看到。            ← 可见范围（用户要求）
[取消]  [保存修改]
```

> **删文字 ≠ 删功能**：`completeStage` / `archiveStageUpdate` / 乐观锁 `expected_version` /
> 照片 `published` 语义 / 阶段顺序强制，**一行代码都没动**。本次只改渲染出的文案与样式。

1. **I-03「切类型下方内容零位移」**：原判据把"未选类型"也算进零位移，靠 208px 占位块对齐。

## 八、踩坑记录（给下一个人，避免重走）

1. **`-webkit-line-clamp` + `min-height` 同时存在会把高度压回内容高**
   想用 `min-height: calc(1.3em * 2)` 撑两行，实测量到 **34px**（= 一行），标签带矮一半。
   最终改用外层 `padding` 补差。

2. **补高度只能补在内容上，不能补在留白上**
   第一版把 53px 全加进卡片 `padding`（上下各 26.5px），截图一看就错：文字与图形挤在中间、上下两圈空。
   最终拆成：流程图 `margin-top` +23px、阶段名标注带 `padding` +48px。

3. **固定 px 补差在另一个视口下必然错位**
   390 下调准 352 == 352，375（iPhone SE）下差 **-2px** —— 字号档位在两档视口间不同。
   最终取中值，两视口最大残差 **2px**，判据按 ±2px 容差（真缺陷是 50px 级别，容差不会放过）。

4. **`build-plugin.mjs` 不构建移动端**
   移动端是 `src-mobile/` 独立 vite 工程，必须 `cd src-mobile && npx vite build`。
   只跑 `build-plugin.mjs` 会让人以为改了却没生效（本轮踩过，一度以为 CSS 没生效）。

5. **仓库文件是 CRLF**
   用 `\n` 拼的多行锚点永远匹配不上；用正则改属性要用 `(?m)^[ \t]*xxx\r?\n`。

## 十、另发现（不阻塞，记录在案）

**门店经理 `arc1.mgr.a` 能打开 `DEMO-R2221-B`（id=395）**，而 395 的 `store_id=1`。
按 `ARCHIVE_READ_ROLES` 的设计，`store_manager` 应当只读**本店**档案；需要确认经理是否绑定到 store 1。
