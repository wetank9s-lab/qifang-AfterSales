### 2.2 最小权限子账号

**不要给主账号密钥。** 需要新建一个仅能写该桶前缀的子账号，策略形如：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": [
        "cos:PutObject",
        "cos:InitiateMultipartUpload",
        "cos:UploadPart",
        "cos:CompleteMultipartUpload",
        "cos:ListMultipartUploads"
      ],
      "resource": [
        "qcs::cos:<region>:uid/<APPID>:<bucket>/prod/postgres-daily/*"
      ]
    },
    {
      "effect": "allow",
      "action": ["cos:GetBucket", "cos:HeadObject"],
      "resource": ["qcs::cos:<region>:uid/<APPID>:<bucket>/prod/postgres-daily/*"]
    }
  ]
}
```

> 刻意**不给** `DeleteObject`：备份端只负责写，删除由桶的生命周期策略做。
> 这样即使服务器被攻破，攻击者也无法通过该凭据抹掉历史备份。

## 三、拿到资源后我会做什么（已设计好，未执行）

1. 安装 `coscli`（单二进制，不依赖 Python/Node）或 `rclone`（若无外网则用离线包）
2. `backup.sh` 末尾追加一步：上传**加密包 + .sha256**，不传明文、不传密钥
3. 上传后用 `HeadObject` 回验 `Content-Length` 与本地一致 → 不一致即告警
4. 每日在 `watchdog.sh` 里核对「本地最新包 vs 远端最新对象」（`LastModified` 差 ≤ 26h）
5. 增加一次**异地恢复演练**：从 COS 拉回最新包 → 在隔离库恢复 → 与本地演练结果比对
6. 全部产物写进验收报告，**上传失败必须触发告警**（不允许静默失败）
