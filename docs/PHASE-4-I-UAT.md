## 2. 四个 UX 观察项（除 §1 的 8 步之外，必看）

### ① 自动生成的「新建 / 编辑 / 删除」按钮是否误导 —— **重点观察，可能是阻塞项**

背景：NocoBase 页面编译器会强制合并 `addNew` / `bulkDelete` / `view` / `edit` / `delete`
五个动作，**无法移除**（`docs/DEVIATIONS.md` DEV-53 坑 2）。这些按钮点下去门店角色会得到 403。

| 观察点 | 记录 |
|---|---|
| 真人**是否**把它们当成正常售后操作？ | ⬜ 是 / ⬜ 否 |
| 若误点，界面的提示是否**看得懂**？（403 原文？还是"操作失败"？） | ____________________ |
| 误点后真人是否**能自行回到**正常流程？ | ⬜ 能 / ⬜ 否 |

> **判定口径（复核方 2026-09-21 裁定）**：若真人把它们误认为正常售后操作、
> 点进去才看到 403，**判为 Phase 4 阻塞性 UX 问题** ——
> 必须在关闭 Phase 4 前**隐藏或改造**，不接受"反正后端会拦"。

### ② 短信异常的可察觉性

背景：`sms.enabled=false` 时派工会成功但短信记 `rejected` + `SMS_DISABLED`（§11.1）。

| 观察点 | 记录 |
|---|---|
| 对方说"派工成功"，但客户其实**没收到短信** —— 真人能否从界面上察觉？ | ⬜ 能 / ⬜ 不能 |
| 他自己是怎么判断"短信发没发出去"的？ | ____________________ |

> 不作为 Phase 4 阻塞项；用于决定 Phase 9 是否需要一个"通知异常"标记。
