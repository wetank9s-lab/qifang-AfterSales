# 工程铁律（验收/断言/编排）

> 每条都对应一次**真实事故**。这里是**跨轮复用**的判据，不是某一次的补丁。
> 单次的定位与复盘见 `docs/DEVIATIONS.md`（DEV-1~74）；本文件只保留**可复用的规则本身**。
> `MEMORY.md` 只列最常咬人的几条，**完整清单以本文件为准**。

---

## A. 断言有效性

1. **断言不会变红 = 没有断言**。凡是"应该有"的东西，都必须有脚本能把它**变红**；写完断言必须做一次
   **反向验证**（人为造出缺陷态 → 断言必须报红 → 还原 → 回绿）。
2. 会误报的检查比没检查更糟。断言比**集合**不比顺序；判"某节点在不在"要用**客户端真正消费的字段**
   （如 flowModels 的顶层 `use`），不能用"插入动作是否成功"。
3. **"读到空"是最坏的假绿**：遍历类断言必须**显式断言** `checked > 0`，否则"一条都没遍历到"会报绿。
4. "跳过"必须与"通过"**分开计数**（独立哨兵、单独打印、明确"不计入通过"）；断言的前置条件
   **不能靠别处残留**满足（机缘巧合的绿 = 跨脚本污染的另一面）。
5. 断言必须与**库龄无关**；盯**契约**不盯实现细节（常量一搬家就假红）。"豁免类"断言必须**同时**
   断言"被豁免的东西确实存在"（DEV-64）。
6. 提示/警告类输出**也要反向验证**：只在**红灯行、且脚本真失败**时才提示，别在成功路径挂假警告。
7. 要断言某字段，先确认接口**真的返回那个键名**（Visit 状态列是 `visit_status`，不是 `status`）。
8. **只读 DOM 文本的"渲染闸门"是半个闸门（DEV-74）**：必须**捕获真实 Network 请求并断言 2xx**；
   否则它回答不了"浏览器实际打的是哪个 URL"，就**不该叫"真实渲染闸门"**。名字必须与它真正
   观测到的东西一致 —— 只读文字却自称"真实"，是**过度承诺**。

## A′. **验证器自己也会错**（DEV-76~79 · P5-1 一次性暴露四个）

单独成节、**不并入上面的编号**（避免重排既有铁律的号，别处引用会全断）。
这四条来自同一个根因，所以放在一起看：

> 用**正则**对**整份** Vue/TS 源码做**语义判断** —— `verify-technician-h5.mjs` 首跑 9 绿 4 红，
> **四条红全是 checker 错，没有一条是产品缺陷**。处置原则是**修"产生断言的验证方法"**，
> 而不是把那四条断言各自打上补丁。

- **V1 · 别在整份源码上撒正则，要分区 + 结构化**（DEV-76 / DEV-76b / DEV-78）。
  SFC 的 template / script / style **注释语法各不相同**；根模板里还**嵌套** `<template v-if>`
  （正则配平会在第一个内层 `</template>` 处截断，后半段"合法地"看不见）。
  典型事故：`/\/\*[\s\S]*?\*\//g` 在 `accept="image/*"` 里遇到 `/*`，非贪婪吃到 `<script>` 的
  `*/`，**静默吞掉 6KB 模板** —— 被吞的那段里写什么都不会被发现（假绿）。
  要判"用户看到什么"，就**真的遍历**（跳过注释 → 解析标签 → 收文本节点 + 可见属性白名单）。
  共用原语见 `scripts/lib/h5-contracts.mjs`。
- **V2 · 断言原语必须"一望而知"**（DEV-77）。`eq(actual, expected)` 用 `!==` 比数组 = **引用比较**，
  于是"报文字段集合"这条断言**永远不可能通过**，而报错里"期望/实际"逐字相同，像见鬼。
  → 拆成 `eqScalar`（严格）与 `eqJson`（结构；键序无关、数组序敏感），
  **不留**那个看着什么都能比的 `eq`。**永远变红的断言与永远变绿的断言一样有害**。
- **V3 · 把门禁的输入做成"双向 fixture"，再证明 fixture 会红**。
  fixture 必须**同时**声明 `accept`（应通过）与 `reject`（应拒绝）；只跑一边的话，
  "永远返回 true 的 checker"也能全绿。然后必须跑**变异测试**：把当年的坑**逐个塞回去**，
  要求 fixture 层变红、且是**预期那条**变红。
  落地：`verify-technician-h5-selftest.mjs`（fixture 层，必跑）+ `verify-technician-h5-mutation.mjs`
  （变异测试，改过 checker 后手动跑）。**凡是出现一次"产品没错、checker 错了"，都要沉淀成 fixture。**
- **V4 · "工具坏了"与"产品坏了"必须分开报**。fixture 红了 → 门禁 **exit 2 且不给产品结论**
  （既不是 PASS 也不是 FAIL）。拿坏掉的验证器去跑"总绿数"，比没有验证器更危险。
  ⚠️ 同理**不许**把"旧的红"自动改写成 PASS —— 必须在新 checker 下重跑取证。
- **V5 · 换行敏感的锚点必须按文件行尾对齐**（本仓库源码是 **CRLF**）。
  脚本里用 `\n` 拼出的多行锚点**永远匹配不上**，表现是"锚点没找到"→ 变异/替换类脚本
  **看着在跑、其实一个都没施放**（又一种假绿，已在 `verify-technician-h5-mutation.mjs` 里踩到并修）。

## B. 环境与编排

9. 脚本要区分"**环境未就绪**"与"**真红灯**"（退出码 0/1/2）；测试工具会**污染环境** →
   **先静态门、后联网**。
10. **编排者要为"跨脚本状态污染"负责**（DEV-63）：`verify-phase3-h5 → smoke` 连跑，smoke 必多出
    "期望 422、实际 429"（约 20s 回填）→ 显式冷却（本项目 25s；跑完 ~30 请求的脚本后紧跟 10 路并发
    需 **40s**）或隔离，**别为此放宽产品限流**。`svc_public` = `30r/m burst=10 nodelay`；
    429 文案有多种（`实际 429`/`HTTP 429`/`RATE_LIMITED`/`TOO_MANY_REQUESTS`），检测正则要放宽。
11. 限流两层，**nginx 先卡**（11 突发 + 0.5/s 回填）；两种 429 要能区分。
12. **`uat-reset-baseline.mjs` 顺序不可反**：`smoke-test` 会**真造工单**，必须"先验证、后复位"。
13. `Exit code 0 ≠ 业务动作发生了`（DEV-61）：清理类脚本必须 ① `-v ON_ERROR_STOP=1`；
    ② 执行后**独立再查**受影响行数；③ 自带前后置断言。
14. 脚本自造失败会**跨轮污染**（DEV-55）：豁免要**窄到具体消息**；反向验证后必须**还原**再跑全绿。
15. **"两遍编译"必须共享同一份选项对象**（DEV-60）：凡用 metafile 反推产物性质，探针与产物构建
    必须是同一份选项（漏 `jsx:'automatic'` → `define` 少声明 `jsx-runtime` → 后台整页 App error，
    而 116 项断言**全绿**）。
16. **"改配置/改环境"类断言的反向验证，必须等改动真的生效再断言**（DEV-74）：`nginx -s reload` 是
    异步的，keep-alive 还会让旧 worker 继续服务 → 缺陷态会读到"好配置"（**反向验证假通过**）。
    要**轮询到实际生效**，且探测要**每次新起进程**（等价于新连接）。

## C. 编码陷阱

17. 返回哨兵值（`0` / `''`）的函数**不能拿 `??` 接兜底**（`0 ?? fallback` 求值为 `0`，兜底永不生效）。
    要用 `if (x) return` 短路或 `||`。
18. **"同前缀"不等于"同值"**：`uat.store.a`（点）≠ `uat_store_a`（下划线）。凡是用"从 A 字段推导
    B 字段"当兜底查找，先确认两者**真的一样**。
19. **复用"构造器"前先问"字段集一样吗"**（DEV-70 P0 根因）：两个动作共用一个只认自己字段集的
    payload 构造器 → 新字段在**出口被静默剔除**。凡"A 复用 B 的 payload/校验构造器"，必须**显式声明
    各自字段集**并断言**差集**。
20. **UAT / 走查的预期本身也要审**（DEV-71）：拿错误预期去测产品会**制造假失败**。例：要求同一张
    工单上"门店自修 + 厂家各提交一次都成功" —— 首次派工后已 `PROCESSING`，第二次 dispatch 本就该被
    状态机拒绝。真人 UAT 只做**一次**真实首次派工，其余合法枚举交给自动化契约断言。
21. **验收证据的引用不可破坏**：走查后回收临时账号用**停用**（撤角色 / 撤映射 / 重置口令 / **保留行**），
    **不物理删除** —— `handler_user_id` / `operator_user_id` 指向它，删了就"说不清是谁做的"。
22. 写库形状有疑问时**读实现**，不要看调用点（`ctx.action.params.values` 与 `modelToSingleNodes` 的
    `...rest` 会给出**相反**结论）。
23. **对产物做断言不要拿中文当锚点**：esbuild 默认 `charset: ascii`，产物里的中文是 `\uXXXX`，
    按中文短语搜**永远搜不到**（实测踩过）。改搜 ISO 时间戳等 **ASCII** 锚点。
24. **探针自身失败必须与产品缺陷分开报**（DEV-66，已三度复发）：生成的脚本先 `node --check`；
    探针自身失败一律标 `probeBroken`，走"**注意**"而**不是**"阻塞"，并明写"这一层本轮没验到"。
    若照探针的假红去改产品，就会**把好代码改坏**，同时掩盖真正的红灯。
25. **静态源码断言要先剥注释**：为解释坑位而写的注释里常含被断言的关键字（如 `/api/`），
    直接 grep 会**假红** → 用先剥 `/* */` 与 `//` 的读取函数再扫。

## D. 交付链（"代码对了"与"用户拿到"之间的那一环）

26. **「改了代码 + 重建了产物」≠「服务端在发新产物」。**
    静态产物 URL 常带 `?hash=`，而该 hash 往往由**产物文件 mtime** 算出
    **且被服务进程缓存**（NocoBase 即如此：`sha256(mtime + APP_KEY + version + appVersion + salt)[:8]`，
    存在 `PackageUrls.items` 这个静态 Map 里）。
    ⇒ **重建产物而不重启服务**时，服务端会继续下发**旧 URL**；若该 URL 的浏览器缓存还在新鲜期内
    （长 `max-age`），**缓存键不变 ⇒ 永远拿不到新产物**。
    - **判据用「时间」，别复算内部 hash**（复算会绑死实现细节，常量一搬就假红）：
      **产物 mtime 不得晚于服务进程启动时间**；晚于即红灯，并给出确切重启命令。
    - 两条处置**必须都做**：① **重建后重启服务**（主措施，URL 随之改变 ⇒ 直接绕开旧缓存条目）；
      ② 该路径**不得长缓存**（兜底）。
27. **凡是写"下一步执行 X"的提示，都要确认 X 真的会生效。**
    踩过：构建脚本收尾提示「下一步：`docker compose up -d`」——
    而 `up -d` 对**已运行且配置未变**的容器是 **no-op**，它**不会重启**。
    一句看起来无害的提示，让人空跑了一整轮真人走查。
    **提示语本身也要被验证**（与第 20 条"验收预期本身也要审"同源）。
28. **探针的运行环境必须与真人的环境对齐，否则它证明不了真人看到的东西。**
    无头探针每次开**全新 profile**（空缓存）⇒ 永远拿最新产物 ⇒ 永远绿；
    真人用**持久 profile** ⇒ 被缓存粘住。**"探针全绿"与"真人报错"可以同时为真**，
    且这恰恰是**缓存/交付类缺陷**的典型特征。看到这种分歧，先问：
    **"探针和真人的环境差在哪？"**（缓存、profile、时区、UA、是否走代理……）

## 如何新增一条铁律

同时满足三条才写进来：① 有**真实事故**可指（能对应到某个 DEV）；② 是**可复用判据**（不是一次性补丁）；
③ 能写成**可执行**的形式（有脚本能把它变红）。只满足前两条的，写进 `docs/DEVIATIONS.md` 即可。
