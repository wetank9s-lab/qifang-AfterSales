## 2. 逐项：已有能力 / 冻结范围 / 真正缺什么

### H5-01 UX-01B / P11-4 上传失败恢复

- **需求来源**：H5-CLOSURE-01 §4-D/§6；UX-01B 遗留。
- **已完成**：媒体-only 组合 **23/23**（报修 4 组 + 投诉）、拒绝语义（格式/超限/伪造会话）、幂等（同 `X-Request-Id` 回放）。
- **冻结/不可重做**：`/api/public/media/session|upload|files` 契约、P11-5 私有流与 Range、四入口 2×2 布局与 SVG 图标。
- **真正缺口**：**注入式**恢复验证 —— 断网、超时、提交接口 5xx、上传成功但提交失败时"媒体不丢"。
  当前只有"代码路径 + 文案存在"，**未验证**。
- **依赖**：CDP 断网/请求阻断 + 上传交互脚本；无需外部资源。
- **门禁**：扩 `verify-h5-closure-media.mjs` 或新增 `verify-h5-upload-recovery.mjs`。
- **真人验收**：弱网真机（可并入 H5-02）。

## 5. 一句话结论

剩下的是两类事：

1. **后台业务化**（BE-01～BE-05）——把"能用"做成"好用"，这些是**新的开发需求**，不是验收缺口；
2. **证据与外部资源**——真机、真实短信、公网 TLS、真实账号、真人 UAT，这些补不出来，只能等条件。

两类都不改变一个事实：已冻结的模块不重做。
