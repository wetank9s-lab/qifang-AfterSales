## 1. 关键诊断：桩从未被调用

本轮在桩内加了自证计数器，结果：

```json
"sends": [],
"hits": { "session": 0, "upload": 0 },
"cards": [{ "s": "网络不太稳定，请点「重试」", "code": "NETWORK_ERROR", "cls": "is-failed" }]
```

- **`sends` 是空的** ⇒ `XMLHttpRequest.prototype.send` 的覆写**一次都没被调用**；
- 但卡片确实报了 `NETWORK_ERROR` ⇒ 说明**确实有一次网络请求 onerror**；
- 两者合起来只能推出一个结论：**这个构建里的上传不走 `XMLHttpRequest.prototype.send` 这条路径**
  （或走了另一个 realm/实例）。

⇒ **不是组件状态机的问题，也不是产品缺陷，是我这套桩对这个 bundle 无效。**
上一轮我把原因归为"匹配规则写错"，**这个判断也不对** —— 匹配规则没错，是**拦截点选错了**。

按令「先确认测试有效性，不直接修改上传业务逻辑」，**我在这里停下**。
