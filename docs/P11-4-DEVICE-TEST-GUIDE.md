## 1. 测试入口（**只在本机局域网内有效**）

生成（会自动调产品自身的 `signStoreEntry` 签发入口，并生成二维码）：

```bash
node scripts/make-device-test-entry.mjs            # 默认门店 S01
node scripts/make-device-test-entry.mjs S02        # 指定门店
```

产出在 `storage/tmp/device-test/`：

| 文件 | 内容 |
|---|---|
| `entry.json` | 入口值 / 局域网 URL / 门店 / 生成时间 |
| `qr-report.png` | 报修页二维码（480px，手机扫码直达） |

**当前环境**（2026-10-14 生成）：

| 项 | 值 |
|---|---|
| 门店 | `S01` |
| 局域网 IP | **`192.168.0.167`**（网卡 `WLAN`，真实网卡） |
| 报修页 URL | `https://192.168.0.167/h5/report?k=<entry.json 里的 entry>` |
| 二维码 | `storage/tmp/device-test/qr-report.png` |

### 🔴 换过 IP 的教训（DEV-189）

第一版脚本用「connect `10.255.255.255` 取第一个地址」来猜本机 IP，
在本机**挑中了虚拟网卡**（Docker/WSL 的 `172.x`、VMware 的 `192.168.190/110.1`），
生成的二维码在手机上**永远打不开**。

现在脚本改为**按网卡名排除虚拟设备**（`VMware|VirtualBox|vEthernet|Hyper-V|Loopback|Bluetooth|TAP|…`），
真实网卡（`WLAN|Wi-Fi|以太网|Ethernet|eth*|wlan*`）优先，并支持手动指定：

```bash
node scripts/make-device-test-entry.mjs            # 自动挑真实网卡
node scripts/make-device-test-entry.mjs S01 192.168.0.167   # 手动指定
```

脚本还会打印**连通性自检**（443 是否在 `0.0.0.0` 监听、网络档案是 Public 还是 Private、
其他候选网卡），并把"若打不开该怎么办"的排查顺序直接印出来。

> **换电脑网络后必须重新跑这个脚本** —— 入口是 IP 相关的，旧二维码会失效。

### 关于防火墙（本机实测结论）

本机存在 `Docker Desktop Backend` 入站规则（`Allow` / `Public` / **`TCP Any` 端口**），
**已经覆盖 443**（因为 Docker Desktop 是通过 `com.docker.backend.exe` 转发端口的）。
⇒ 手机连不上时**先怀疑网段/地址，再怀疑防火墙**。

若排查后确认是防火墙（例如换了 Docker 版本或规则被清掉），用**管理员 PowerShell** 补一条：

```powershell
New-NetFirewallRule -DisplayName "svc-ticket 443" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow -Profile Any
```

（这属于改系统配置，需要你自己执行；脚本只做**只读**检查，不会动你的防火墙。）

### 前置条件（缺一不可）

1. **手机与这台电脑在同一个 Wi-Fi / 局域网**；
2. 手机浏览器打开时会提示证书不受信任 ——
   这是**自签演练证书**（见 `docs/SECURITY.md` 与 `verify-tls.mjs`），
   需手动点「继续访问 / 高级 → 继续」；
3. ⚠️ **短信里的进度链接目前指向 `http://localhost:8080`**（`.env` 的 `PUBLIC_BASE_URL`），
   **手机打不开**。若要在真机上验证"短信链接可用"，先临时改：

   ```bash
   # .env
   PUBLIC_BASE_URL=https://192.168.4.101
   docker compose restart app
   ```

   ⚠️ 跑完**务必改回** `http://localhost:8080` 再重启 ——
   生产档会断言 `PUBLIC_BASE_URL` 不是内网/打不开的地址。
   （真机验证"短信里的链接能打开"这件事**只有在改了它之后**才成立；
   未改之前的短信链接**预期打不开**，这不是缺陷。）

## 2. 逐项操作步骤与**预期**结果

四个环境各跑一遍：**iPhone Safari · Android Chrome · iPhone 微信 · Android 微信**。

> 说明：微信内置浏览器用的是**标准 HTML 媒体采集能力**
> （`<input capture>` / `getUserMedia + MediaRecorder`），
> **不必然需要**公众号 JS-SDK。只有确实需要 `wx.*` 时才需要域名/签名/权限前置条件 ——
> 本轮的实现**没有**依赖任何 `wx.*` 接口。

### 第 1 项 · 拍照

| 步骤 | 预期结果 |
|---|---|
| ① 扫二维码打开报修页 | 页面正常显示门店名，出现「拍照 / 录音 / 拍视频」三个按钮 |
| ② 点「拍照」 | 首次弹一次性授权（「使用相机和麦克风」）→ 点「继续」 |
| ③ 授权后 | **直接打开相机**（不是文件管理器）；只能弹系统媒体选择器时也算可用（降级） |
| ④ 拍一张 → 返回 | 表单区域**就地出现**照片缩略图 + 「查看 / 删除」 |
| ⑤ 再点「拍照」两次 | 可以继续拍，累计 3 张后按钮变灰并提示"照片已满 3 张" |

**待验证**：真机是否走原生相机（`capture=environment` 的实际行为因浏览器而异）。

### 第 2 项 · 录音

| 步骤 | 预期结果 |
|---|---|
| ① 点「录音」 | 系统弹麦克风权限（iOS 每次会话首次） |

| ④ 点播放器 | 能听到刚才的录音 |

**待验证**：iOS Safari 的 `MediaRecorder` 产出 **mp4/m4a**（服务端已按容器内容支持 mp4 分支，
但**从未用真机字节验证过**）；Android Chrome 产出 **webm/opus**（本轮已用真实 Chromium 字节验证 ✓）。

### 第 3 项 · 拍视频

| 步骤 | 预期结果 |

| ① 点「拍视频」 | 打开录像界面（原生相机） |
