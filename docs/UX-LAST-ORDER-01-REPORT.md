## 一、实现了什么

### 1.1 客户侧（报修/投诉 → 成功页 → 再次扫码）

| 功能 | 实现 |
|---|---|
| 默认不保存 | 成功页出现「在此设备记住这张工单」，**两个开关默认都不勾选**；不勾选时**不写任何存储** |
| 第二个开关 | 「下次打开本店页面自动进入上一单」，默认关闭，且**未勾选"记住"时不可用** |
| 按门店分区 | 成功页 URL 从报修页带上 `sc=<服务端解析出的门店 code>`；存储 key = `svc.lastOrder.v1.<storeCode>` |
| 重开同店入口 | 报修页在门店解析成功后再读本机记录，**先调既有进度接口验证**；通过后显示「上次提交的工单 + 查看上一单进度 + 不再记住」 |
| 自动进入 | 仅当 `autoOpen=true` **且验证通过**才 `replace` 进进度页；验证失败/网络错误绝不自动跳 |
| 失效处理 | 401/404/410 ⇒ **删除本机记录**并提示"已失效，已从本设备清除"；网络/5xx ⇒ **保留记录**、不自动跳、提示稍后重试 |
| 链接优先 | URL 带 `?pt=` 时，本机记录不参与（成功页/进度页语义不变） |
| 清除 | 卡片上「不再记住」；删除后卡片立即消失并提示 |
| 隐私 | 只存：`storeCode / ticketNo / token / ticketType / createdAt / savedAt / autoOpen / v`；**不存姓名、手机号、地址、故障描述** |
| 无跨设备承诺 | 文案明确"只保存在本浏览器，换手机/浏览器无法找回；公共手机请勿勾选" |

### 1.2 师傅侧（仅本地摘要，不含 Token）

- 提交成功后写 `svc.tech.lastDone.v1 = { ticketNo, completedAt }`（**无 Token、无客户资料**）；
- 成功页显示"已在本机记录：上一单已完成（时间）"；旧链接失效页显示"本机记录：您曾于…完成过一次服务，**这里不提供详情**；如需回看请让门店重新签发只读回执链接"；
- 可「清除本机记录」；
- **没有**新增匿名历史详情接口；**没有**用 localStorage 重放失效 Token；旧链接仍按服务端规则 401。

### 1.3 未新增的东西

- 没有新接口、没有新数据表、没有改 `PROGRESS_TOKEN` 生命周期、没有按手机号/单号开放查询。

补充事实（本轮新发现，已写进用例）：

- **同一标签页**重开旧链接**不会**进失效页：`sessionStorage` 里有 `svc.tech.submitted.<token>`，
  产品会显示"已提交"成功页（有摘要、无 Token）。这是有意设计，已单独断言；
- 失效页只在**换设备 / 新开浏览器**（`sessionStorage` 为空）时出现，用例显式清空后再导航，
  并在输出里标明"已清空 sessionStorage（模拟换设备 / 新开浏览器）"。

### 2.4 客户侧门禁稳定性：修复"门禁自己打满对客限流"

HOLD 后重跑时，视口段出现 **2 次"门店卡未出现"超时**（一次 420、一次 390，非固定视口）。
去翻 nginx 日志才看清根因：

```
"GET public-api" 429 77 "https://127.0.0.1/h5/report?k=S01.…"
```

即 `svc_public limit_req zone rate=30r/m burst=10`（**对客承诺，未改**）被本门禁自己打满：
视口段原来**每个视口都重新加载一次报修页**，每次加载都打一次入口接口。

修法（只改验证方法，不改产品、不放宽阈值）：

1. 视口段改为**一次加载 + 三种视口测量**（`Emulation.setDeviceMetricsOverride` 后重排），
   断言语义不变（仍是"卡片存在且 `scrollWidth <= innerWidth`"），请求数从 3 次降到 1 次；
2. `openReport()` 改为等 `store-card` **或** `entry-error` 任一出现即判定，
   识别到 429 时**显式打印"入口被限流，退避 5/10/15s 后重试"**，重试仍失败则变红；
   不再把限流伪装成"门店卡坏了"干等 40 秒。

复跑证据：

| 运行 | 结果 | 429 |
|---|---|---|
| 单跑 | 24/24 | 无 |
| 背靠背第 1 轮 | 24/24 | 无 |
| 背靠背第 2 轮 | 24/24 | **2 次**，均"等 5s"后重试通过 |

> 没有为了变绿去放宽 `svc_public`；限流仍是 30r/m burst 10。

## 四、安全边界自查

| 项 | 结论 |
|---|---|
| 未经同意保存 Token | ❌ 不会：必须勾选；未勾选时无任何写入 |
| S01 记录串到 S02 | ❌ 不会：key 与门店 code 绑定，且 code 来自服务端解析 |

| 客户资料落盘 | ❌ 不会：只存单号/Token/门店/类型/时间 |
| 师傅旧 Token 复活 | ❌ 不会：不存师傅 Token；旧链接仍由服务端判定失效 |
| 新增匿名查询面 | ❌ 无：复用既有进度接口 |
| 日志/埋点/第三方 | 未新增任何日志或外发请求 |
