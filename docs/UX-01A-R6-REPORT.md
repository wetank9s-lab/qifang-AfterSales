## 一、P0 —— 工单详情弹窗被遮挡：**根因已定位并修复** ✅

### 1. 真实根因（真实浏览器取证，非猜测）
在门禁里加了"卡片弹窗 → 工单号 → 详情必须在最上层"的断言，用 `elementFromPoint` 判定**鼠标实际命中的最上层元素**，并打出层级：
```
✗ **被遮挡**：drawerZ=1000 · drawerMaskZ=1000 · modalZ=2000 · elementFromPoint 命中的是「ant-modal-wrap」
```
**根因**：`openTicketDrawer()` 用 `ReactDOM.render` 把抽屉渲染在**应用树之外**的裸容器里，
因此**拿不到宿主 ConfigProvider 的 z-index 层**——宿主弹层在 **2000** 层，而该抽屉退回 antd 默认基值 **1000**
⇒ 天然被压在下层。**这是"跨渲染树丢上下文"，不是 CSS 写错，也不该靠"调一个更大的 z-index"掩盖。**

### 2. 修改位置与方案
- 文件：`src/client/ticket-drawer.tsx`（`openTicketDrawer`）。
- 方案：打开时**读取当前已打开浮层的最高 z-index**（`.ant-modal-wrap/.ant-modal-mask/.ant-drawer` 的 `getComputedStyle`），
  把抽屉的 `zIndex` 设为**该最高层 + 1**（透传 `Drawer.zIndex`；`Drawer` 是既有已核实导入，未新增宿主导入）。
  - 无浮层：基值 1000 → 抽屉 1001（**与原先一致，无回归**）；
  - 有 2000 弹窗：抽屉 **2001 ⇒ 在最上层**。
- **不是"极大值"魔法数字**：它对齐"当前最高浮层"，仍由框架的层级语义决定；未隐藏任何遮罩、未关掉原窗口。
- **中央修复 ⇒ 一次修好所有入口**：工作台卡片弹窗、`处理`/`跟进` 窗口内的查看入口、`我的门店工单` 行内入口**全部受益**（都走同一个 `openTicketDrawer`）。

### 3. 修复证据（真实浏览器，同一断言）
```
✓ P0 卡片弹窗 → 工单号 → 详情在最上层 —— drawerZ=2001 · modalZ=2000
✓ ①b 点击工单号打开**本行**只读详情 —— 抽屉标题「工单 FW20261016-0006」
✅ 全部通过：46 项
```
- 构建：TS 门禁 ①未声明=0 / ②宿主包具名导入违例=0 → **✅ 通过** + esbuild ✅；`restart app` health 200。

  （`ConfigProvider` 不在已核实的宿主导出名单内）——门禁正常工作，已改用 `Drawer.zIndex` 实现。
