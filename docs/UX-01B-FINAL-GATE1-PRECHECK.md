## 4. 副作用风险

| 通道 | 状态 | 判断 |
|---|---|---|
| **短信** | `SMS_PROVIDER=**mock**`、`SMS_ENABLED=**false**` | **绝不会真发** ✅ |
| 邮件 | 未配置任何邮件 provider | 无 ✅ |
| WebHook | 未见配置 | 无 ✅ |
| 派工 | 由后台人工操作触发，**无自动派工** | 建单不会自动派 ✅ |
| **SLA 扫描** | **有定时任务** `sla-scan-scheduler` | ⚠️ **会扫到测试工单** |
| 评价超期 | `review-expiry-scheduler` | 只处理"已完成待评价"的单，新建单不受影响 |
| 短信重试 | `sms-retry-scheduler` | 受 `SMS_ENABLED=false` 约束，空转 |

**唯一需要留意的**：SLA 扫描会按时间规则给工单打标记（超时/临期）。**测试工单如果在库里停留超过扫描窗口，可能被打上 SLA 标记**——这属于"测试产生的派生数据"，清理时要一并处理。
